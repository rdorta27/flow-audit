700 of 5,000 orders have a problem that a person has to fix by hand

Flow Audit read 5,000 orders from Order manager, Activation system (3 sources) and looked for 3 patterns that make people redo work by hand. Measured: the orders and records counted in the data. Hours are an estimate that only helps rank what to fix first; they rest on the assumptions below. Flow Audit finds and measures; fixing the cause is the operator's work.

  • What was audited. 5,000 internet orders (a customer's request to get an internet service installed and switched on), read from Order manager, Activation system. Period: 2026-09-01 to 2026-09-30.
  • What went wrong. 700 of them needed a person to fix something by hand. The most common problem is Activation fails and nobody retries (R01), in 400 orders.
  • Where to start. Activation fails and nobody retries: Retry a failed activation automatically, or raise it to a queue a person owns, within the retry window.

Most orders affected

  1. Activation fails and nobody retries (R01) Measured 400 orders: An activation failed and nothing tried it again within the retry window, so a person has to find the order and push it through by hand.
  2. No end-to-end correlation id (R05) Measured 300 orders: Some records cannot be tied to their order by an id they carry, so a person has to work out which belong together.
  3. Duplicate service order (R04) Measured 20 orders: A second service order exists for the same order line. When activation failed, a retry created a new order instead of reusing the first.
